`[data-layout="<id>"]`.

## How a page picks its look

```html
<html data-layout="curling">                          <!-- follows the visitor's light/dark setting -->
<html data-layout="curling" data-theme="dark">        <!-- the visitor pressed the sun/moon button -->
<html data-layout="curling" data-league-colour
      style="--st-league-color:#1F5FA8">              <!-- the league set its own colour -->
```

* `data-layout` is one of `basketball curling hockey slopitch classic scoreboard`.
* `data-theme="light|dark"` is optional. With none, the page follows
  `prefers-color-scheme`, which works with JavaScript off. The sun/moon button sets
  `data-theme` and saves `st-theme` in `localStorage`.
* `data-league-colour` is set exactly when the league sets a colour. Without it a
  layout is the approved mockup look; with it the layout re-derives its accents from
  the league colour (see below).
* Each layout file holds its dark values twice: an `@media (prefers-color-scheme: dark)`
  block with `:not([data-theme="light"])`, and a `[data-theme="dark"]` block. CSS cannot
  share one declaration between the two. `scripts/check_contrast.py` fails if the copies
  differ, including in the custom-colour blocks.
* Layout selectors sit on the element carrying `data-layout`, so the design-system page
  can place many wrappers side by side.

## Token roles

Every custom property is `--st-<role>`. Parts read roles only; there is no raw hex in
`base.css` or `parts-*.css`, and no `!important`. A layout file gives each role a value for
light and for dark. `python scripts/check_contrast.py --tokens` lints the roles (undefined,
unused, raw colours in the parts CSS).

| Group | Roles |
|---|---|
| Ground | `bg`, `bg-image` (pebbles, chalk rules; default none), `surface`, `surface-2` (period bands, hover), `line`, `line-strong` |
| Text | `text`, `muted`, `link`, `link-hover`, `accent` (big numbers, rank numbers), `hot` (second accent: stolen-end text, hot tile edge), `rule` (the 2 px rule under table heads), `focus` |
| Buttons | `button-bg`, `on-accent` (text on `button-bg`) |
| Header | `header-bg` (colour or gradient), `header-text`, `header-muted`, `header-line`, `header-button-line`, `tab` (active underline), `nav-bg`, `nav-text`, `nav-muted` (Classic's separate nav bar; others leave `nav-bg` transparent) |
| Panel (next game) | `panel-bg`, `panel-text`, `panel-muted`, `panel-label`, `panel-row`, `panel-line`, `panel-tile-bg`, `panel-tile-text` |
| Footer | `footer-bg`, `footer-text`, `footer-muted`, `footer-link`, `footer-line`, `footer-accent` |
| Marks | `mark-bg`, `mark-text`, `mark-line` (stolen end, run-limit inning, scoring highlight), `won-line` (won-period underline), `blank-bg`, `badge-bg`, `badge-text`, `win-bg`, `win-text` |
| Rank | `rank-bg`, `rank-text`, `rank-1-bg`, `rank-1-text` |
| Bars | `bar-track`, `bar-fill`, `bar-lead` |
| Score board | `score-bg`, `score-text`, `score-dim` (losing side), `score-line` (Scoreboard digits, hockey and curling total cells) |
| Scenes | `scene-image`, `scene-image-footer` (data-URI SVGs, one per theme, no file paths) |
| Team | `team-1` ... `team-6` (tuned per layout and theme), `team-lift`; `team` is set by `st-team--N` or `st-team--custom` |
| League | inputs `league-color`, `league-color-dark`; derived `league-base`, `league-dim`, `league-lift`, `league-tint`, `league-wash`, `league-ink`; knobs `dim`, `lift`, `tint`, `wash` (percentages, per layout) |
| Layout accent | `layout-accent` (set by the layout, never by a league), `layout-accent-dark` (optional; no layout sets it), derived `layout-accent-base`, `layout-accent-tint` |
| Type | `font-display`, `font-body`, `font-num`, `w-display`, `w-strong`, `display-transform`, `display-tracking`, `num-variant`, and the `fs-*` roles (`micro label meta small table body name h3 h2 title stat score-card score-hero`) bound to the `step-*` scale |
| Shape | `radius-card`, `radius-panel`, `radius-chip`, `radius-sm`, `radius-xs`, `radius-pill`, `border`, `border-strong` |

3 (chip) 4 8 10 12 and pill; tap target 44.

## League and team colours

### The league's colour

A league sets one colour, `colour`, and optionally `colour_dark`, in `league.yml`. Stage 4
writes them as an inline style on `<html>` (`--st-league-color`, `--st-league-color-dark`)
and adds the attribute `data-league-colour`.

* **Without the attribute** a layout is the approved mockup look: its own default colour
  (Basketball blue, Classic navy, Curling house blue, Hockey blue-line blue, Slo-pitch green,
  Scoreboard red).
* **With the attribute** (custom-colour mode) each layout has `[data-league-colour]` blocks
  that re-derive every role that depends on the colour, so that any colour with white text on
  it at 4.5:1 or better passes every pair in `docs/contrast.md`, in both themes. Text on the
  league colour is always white.
* **The layout accent** (`--st-layout-accent`) is owned by the layout and is not a league
  setting: Basketball coral, Classic burgundy, Curling house red, Hockey kickplate gold,
  Slo-pitch clay, Scoreboard amber. An earlier idea of a second league colour (`colour_2`)
  was dropped.
* **Dark theme.** With no `colour_dark` the dark theme derives from `colour` (lifted or
  tinted by the layout's knobs). `colour_dark` replaces it.

What the league colour drives, per layout:

| Layout | League colour drives | Fixed by the layout |
|---|---|---|
| Basketball | header bar (top of the gradient; a night sky in dark), links, big numbers, table rule, buttons, focus ring, next-game and score panels, badges, bars, rank 1 | coral accent (tab underline, hot edge, marks), sunrise stops, hills and court arcs |
| Classic | nav bar, next-game and score panels, links, big numbers, table rule, buttons, focus ring, rank chips, bars, badges | white header bar, white tab underline, burgundy marks and lead bar |
| Curling | links, big numbers, buttons, focus ring, WIN badge, rank 1, won line, badges; the table rule only in custom-colour mode (the mockup's is ink) | ink header, panel and footer; red line and stolen-end marks (layout accent) |
| Hockey | links, table rule, focus ring, buttons, WIN badge, badges, won line, leader bar, rank 1 | boards, red line, gold kickplate (layout accent), rink lines |
| Slo-pitch | header, next-game panel, links, big numbers, focus ring, buttons, WIN badge, rank 1, leader bar, won line | scorebook-ink footer, clay accent, the arc in the header scene |
| Scoreboard | header bar, nav, buttons, highlight text (`hot`), hover link, dark-mode links, focus ring, footer accent | ink, white and grey; amber digits and tab underline (layout accent) |

The tokens that do the maths (`tokens.css`): `league-base` (the colour in use this theme),
`league-dim` (toward black), `league-lift` (a little toward white), `league-tint` (well toward
white: the colour as text on a dark page) and `league-wash` (nearly white: a pale fill). They
use `color-mix(in oklab, ...)`. The percentages are per-layout knobs (`--st-dim`, `--st-lift`,
`--st-tint`, `--st-wash`) so a layout can match its approved dark palette.

### Checking a colour: `check_league_colour`

`scripts/check_contrast.py` runs a layout in custom-colour mode with the league's colour and
reports what fails. Stage 4's data check calls it:

```python
from scripts.check_contrast import check_league_colour
problems = check_league_colour("classic", "#C98A12")     # (layout, colour, colour_dark=None)
for p in problems:
    print(p.message)
```

It returns an empty list when the colour is fine. Each problem names the `league.yml` setting
and says which way to go. One of the messages for Gold (`#C98A12`), which fails in every layout:

```
league.yml colour #C98A12: white text on it is 2.9:1 in the light theme (needs 4.5:1). Pick a darker colour.
```

In the dark theme the message points at `colour_dark` instead: `Set colour_dark to a darker
colour (the dark theme uses colour until you do).` Only pairs that pass with the layout's own
colours and fail with the league's are reported, one message per role and theme.

### Browsers without `color-mix()`

Every league-derived role and every mark tint uses `color-mix(in oklab, ...)`. Browsers older
than Safari 16.2, Chrome 111 and Firefox 113 do not understand it. `assets/css/fallbacks.css`
is loaded last and holds an `@supports not (color: color-mix(in oklab, red, red))` block with
literal values for every colour property, worked out for each layout's default colours. On
those browsers a league loses its own colour and gets the layout's default look, and a custom
team colour is shown without its dark-theme lift, but the page stays readable (every text pair
is checked at AA). The file is generated: run `python scripts/build_css_fallbacks.py` after
changing a layout, and `python scripts/check_contrast.py` fails when the file is stale.

### Team colours

* **Palette colours.** Each layout has six team colours, `team-1` to `team-6`, tuned for light
  and dark and in the order of `docs/dark-palettes.md`. A team without a colour takes a slot:
  `<span class="st-chip st-team--3">`.
* **A team's own colour.** `<span class="st-chip st-team--custom" style="--st-team-hex:#D9621A">`.
  In dark mode the colour is mixed toward white by the layout's `--st-team-lift`, so dark
  colours (navy, black) stay visible on dark cards. It does not depend on the league colour
  and it persists when the league changes layout.
* **Lift per layout** (light is always 0%):

  | Layout | Dark lift |
  |---|---:|
  | Basketball | 53% |
  | Classic | 53% |
  | Curling | 54% |
  | Hockey | 35% |
  | Scoreboard | 52% |
  | Slo-pitch | 30% |

  Each layout file has a table of what the lift does to sample colours. In Basketball,
  Classic, Curling and Scoreboard pure black sets the value: it needs about 51-54% to reach
  3:1 on the dark cards. Hockey (35%) and Slo-pitch (30%) are tuned so that navy, green, brown,
  purple and red reach 3:1 and light colours stay strong; a black chip stays at about 1.2:1
  there.
* **Palettes belong to the layout** (see decision 3 below). Classic uses Curling's six,
  Scoreboard uses Basketball's five plus a grey, and Basketball has a sixth colour (magenta)
  that the dark-palettes doc does not list.
* The chip never carries information alone: the team's name or code is always beside it.

## Part anatomy

Class names are the contract between the CSS, the specimens and stage 4. BEM with an `st-`
prefix: `.st-block`, `.st-block__element`, `.st-block--modifier`, state classes `is-*`.
A layout restyles a part through tokens first, and with a `[data-layout="<id>"] .st-...` rule
only where the mockup differs in shape. The reset in `base.css` uses `:where()`, so it has no
specificity and a part's own margin wins. Links inside parts use `.st-page a.st-x` to beat
`.st-page a`. Local helper properties (`--ls-*` in the line score, `--hm-*` for the hammer,
`--fp-*` in the final panel head, `--ng-*` in the next-game panel, `--row-*` in the game row,
`--tile-edge` and `--tile-ink` in the leader tile) are aliases of roles, never new colours.

Checks made during the stage 3 review, at 360 and 390 px in all six layouts: no sideways page
scroll; every link and button at least 44 x 44 px (links inside a note excepted); every
scroll box has `role="region"`, `aria-label` and `tabindex="0"`; every `th` has `scope`.
Repeat the screenshot sweep after any CSS change.

### Scores

* **Result card** `a.st-card.st-result-card` (the whole card is the link): `__head` (slo-pitch eyebrow
  "Final · Diamond 1"), `__team` (+ `is-winner`) = `.st-chip`, `__name`, `__score`; `__foot` = `__note` +
  `__link` (the chevron is `span.st-chevron`, hidden in Classic). Variants: `--lines` (the card holds a
  `.st-line-score--card` instead of two score rows: curling, slo-pitch), `--tie`, `--hero`.
  The hero (`div.st-result-card.st-result-card--hero`, not a link; the "Box score" `a.st-button` is the
  target) has `__eyebrow`, `st-final__head st-final__head--board` (reused), `__periods` > `li.st-period-tile`
  (`__label`, `__pair` with `.is-lead` / `.is-dim`) for quarters and periods, or a `--card` line score
  for ends and innings, and `__top`.
* **Final panel** `section.st-final` > `__head` (`__status`, `__sub`, `__team` x2 [`is-winner`] = `__name`
  + `__record`, `__score` = `__num` [`is-first` / `is-second`, `is-dim` on the loser] + `__sep`) and
  `__body` (`__titlerow` = `__title` + `__meta`, `.st-line-scroll`, `__foot` [`--split`], `__note`).
  One markup for every layout; layouts reshape it.
* **Line score** `table.st-line-score.st-line-score--<quarters|ends|periods|innings>` with `--card`
  (compact, inside a result card) or `--full`. `.st-line-scroll` is the scroll box
  (`role="region"`, `aria-label`, `tabindex="0"`, except inside a link). Parts: `__team` (sticky first
  column, chip + name), `__total`, `__extra` (slo-pitch R is `__total`, H is `__extra`), `__open` (the
  word "open" under an inning number), `__n` (wraps a marked number so a layout can circle it). Row
  classes `is-winner` / `is-loser`; cell classes `is-won` (won the quarter or end), `is-mark` (stolen
  end, run-limit inning), `is-blank`, `is-void` (X, not played), `is-open` (open inning). Hammer
  marker: `svg.st-hammer` (`__ring`, `__mid`, `__core`) in the team cell or the end cell. Legend:
  `.st-legend` > `__item` > `__key--won|mark|blank|limit|x|text`; `--stack`, `--full`.
  A marked cell is never colour alone: it has a tint, a visible frame in `mark-line` (1 px on a card,
  2 px on the full size) and hidden words in the markup. Slo-pitch draws a circle (an underline on a
  card) and Scoreboard a 2 px amber outline instead.
* **Event log** (hockey scoring summary): `.st-events` > `__group` > `h3.__head` (`<span>` period +
  `__tally`) + `ol.__list` > `li.st-event` (`__time`, `__team` = chip + `abbr.st-team-code`, `__who` >
  `__name` and `__sub` for assists, `__score`); GWG is a `.st-badge`. The penalties table is
  `.st-table.st-table--events` with `.st-table__strong`; the player cell holds the chip and the team
  code, and a `.st-legend` of chips follows.
* **Roster** (curling lineups): `.st-roster` > `a.__head` (chip, `__team`, `__link`) + `ol.__list` >
  `li.__row` (`__role`, `__name` [`is-key` = skip, bold]; a spare is `.st-badge.st-badge--outline` +
  `__for`).
* **Game-page tables**: `.st-table--box` (number column and player column both sticky: box score and
  batting order), `.st-table--numbers` (the game in numbers), `.st-table--events`. Cell helpers
  `.st-table__strong`, `.st-table__big`, `.is-hot` (stolen-end text), `.is-key`, `a.st-player` (44 px
  target without changing the row height); `tfoot` totals. Also `.st-team-heading` (+ `--sm`) = chip +
  `__name` + `__score`; `.st-game-block`; `.st-facts` > `__row` > `__label` + `__value` (+ `__team`);
  `.st-top-scorer` (`__main`, `__label`, `__name`, `__detail`, `__value`, `__num`, `__unit`; the name
  is a link that stretches over the whole tile, or a plain `span` in a past season; two tiles for a tie are
  spaced by `.st-top-scorer + .st-top-scorer`); `.st-note--intro`.

### Data

* **Standings** `.st-table-wrap.st-table-wrap--standings > table.st-table.st-table--standings`: the first
  cell is a `th scope="row"` with `.st-rank` + `.st-chip` + `.st-table__team`; key column cells have
  `is-key`; the note below is `.st-note`. **Race** (Scoreboard's standings): `ol.st-race` > `li` >
  `a.st-race__row` (`--lead` for first) = `__rank`, `__who` > `__name` + `__sub` (record), `__bar` >
  `__fill` (style `width:NN%`), `__points`.
* **Leader tile** `a.st-leader-tile`: `__label`, `__value`, `__name`, `__meta`; the modifier `--hot` or
  `--accent` picks the top-edge colour. Grid wrapper `.st-leader-grid` (2 columns); `.st-leader-group`
  is a small label above a grid (for example Goalies).
* **Leader row** `.st-leader-lists` > `.st-leader-list` > `__title` + `a.st-leader-row` = `__rank`, `__who`
  > `__name` (+ `__team`), `__value` (+ `__unit`). Hockey's points leaders are a `.st-table--leaders`
  with `.st-rank-chip` (round, `is-first` gold) and `.st-leader-cell`; Scoreboard's are `.st-leader-board`
  rows (`__row` [`--first`], `__value`, `__who`, `__name`, `__sub`, `__pill`, `__digits`) with a
  `.st-leader-more` button.
* **Game row** `.st-game-row` = `__surface` (Sheet A / Diamond 1 / Pad 2; `--tile`, `--label`, `--icon`
  or `--tag`), `__teams` (+ `__vs`), `__time` (+ `__sub`); `--no-surface`, `--no-time`; a list on the
  page is `.st-game-rows--list`. It is a CSS grid with named areas `surface teams time`, so a layout
  can reorder (Scoreboard puts the time first).
* **Next-game panel** `.st-next-game`: `__head`, `__label`, `__date`, `__where`, optional `__group-label`
  (curling groups draws by time), `__rows` of game rows, `__foot` (bye note, link), optional `__emblem`

'Roles' are the token roles a part reads. Pixel sizes below are the mockup's; the CSS snaps most of

text says a part has no role of its own, the closest existing role is used (listed under

## Deviations from the mockups

Gaps and changes that are still true in the CSS. The colour changes made for contrast are in
[Mockup colours changed for AA](#mockup-colours-changed-for-aa).

**Shell**
* There are no ticker roles. The ticker uses `footer-bg`, `footer-link`, `footer-muted` and `score-text`. The mockup's tag was a pink league tint; it is amber now.
* Badge colours have no roles: the monogram text uses `--st-league-color` (the light input, so it is AA on the white disc in both themes); rings use `--st-tab`, `--st-link`, `--st-hot` and `--st-league-base`.
* The mockup logos (curling house, hockey rink, slo-pitch seams) are approximated with rings (box-shadow) around a text monogram; the clay dashes on the slo-pitch badge are left out.
* Nav and footer links are at least 44 x 44 px, so the gaps between short links are slightly wider than the mockups (their nav links were 40-42 px tall).
* Curling and Classic move the footer where line under the name with `order`, instead of using separate `__meta` markup.

**Scores**
* The 3 px hockey boards and 30 px radius are literals (no token). The hammer marker rings use `link` (outer) and `hot` (core) instead of two literal blues and reds.
* The hero card is shown for curling and hockey with their first result (the mockups only draw basketball and slo-pitch).
* Curling Home cards have no rule under the head in the mockup; the card size uses a 1 px `line` rule instead of the 2 px `rule`.
* Scoreboard hides chips in cards, hero, roster and line scores (as the mockups) but keeps them, with a team code, in the event log and the penalty table.
* The slo-pitch final line score keeps an opaque team column (white) over the ruled paper lines so the fixed column stays readable when scrolled.
* No role exists for a rink or boards colour: hockey boards use `score-bg`, rink lines use `link` (blue) and `hot` (red).
* Tint boxes inside panels are `color-mix(panel-text 9%, panel-bg)`, not `panel-row`, because sticky cells need an opaque fill.
* There is no "total cell" fill role: curling uses `surface-2` + `score-line`, hockey `score-bg`, slo-pitch `surface-2`, Scoreboard `panel-text` on `score-bg`. There is no "blank end" text role: header text on a blank column uses `text`.
* `--st-focus` is replaced by `panel-text` in the final panel and the hero.
* The curling sample's "Scored with hammer" for Hurry Hard is 3 of 5; the mockup printed 2 of 5 (see decision 7).

**Data**
* Scoreboard's dark lead row has a thin amber outline in the dark mockup; it is not drawn (no role for it).
* Classic-Curling's tiles have no edge in the mockup, Classic-Hockey's do; Classic takes the hockey look for both.
* The slo-pitch Scoreboard mockup puts the tag first in a game row; Scoreboard puts the time first and the tag after it.
* Basketball-Scoreboard's mockup next-game rows are plain lines and slo-pitch's are grey boxes; grey boxes everywhere. The slo-pitch Scoreboard mockup has no black title bar (venue top right); the bar is used for both.
  In the dark theme Scoreboard's `panel-bg` equals `surface`, so the bar is separated only by its position.
* `panel-label` is grey in Scoreboard, but the mockup's title-bar date and lead rank are amber: both use `--st-score-text`. A role such as `panel-accent` would be cleaner.
* There are no emblem roles: the house rings use `link` (blue), `panel-text` (white) and `hot` (red); the face-off circle uses `hot`. This depends on `hot` staying the red line colour in hockey and curling.
* Rank 1 in Classic dark is a light circle (`rank-1-bg`), not the dark one in the mockup.

## Type notes

The scale has 15 steps (11 to 72 px, in `rem`) and the `--st-fs-*` roles are bound to them. Most mockup sizes are within 1 px of a step and are snapped to it; the comment `/* mockup: NNpx, within 1px of the step */`
marks those (for example 19 px to 20, 23 to 24, 25 to 24, 18 to 17). These sizes are off the scale on purpose and kept as `rem` literals, so they still follow the visitor's text size:

| Where | Size | Why |
|---|---|---|
| Classic brand name (`parts-shell.css`) | 22 px | the mockup; no step between 20 and 24 |
| Scoreboard footer name | 22 px | the mockup |
| Ends and innings line-score cells, hockey ends/innings (`--ls-fs`) | 22 px | the mockup |
| Curling ends line-score total (`--ls-tot-fs`) | 30 px | the mockup; between 28 and 32 |
| Final panel separator (`.st-final__sep`) | 0.5em | half the score beside it |
| Curling roles `fs-h2`, `fs-title`, `fs-stat`, `fs-score-card` | 26, 29, 42, 22 px | marked `/* mockup: NNpx */` in `curling.css` |

## Contrast

`scripts/check_contrast.py` resolves every colour role the way a browser does (rules by specificity and source order, `var()`, `color-mix()` in oklab, gradients, translucent colours composited over what
they sit on) and measures every text, large-text and UI pair the design needs, for each layout in light, dark and (for the dark blocks) the OS preference. It also runs every layout in custom-colour mode with
example league colours, lints the tokens, checks that the two dark blocks of each file are identical, and checks the browsers-without-`color-mix()` fallback.

```
python scripts/check_contrast.py                    # run everything and write docs/contrast.md
python scripts/check_contrast.py --check            # same, but write nothing; fail if docs/contrast.md or fallbacks.css is stale
python scripts/check_contrast.py --tokens           # token lint only
python scripts/check_contrast.py --fallbacks        # only the browsers-without-color-mix() run
python scripts/check_contrast.py --verify-browser   # also compare the maths with Chromium (needs Playwright)
python scripts/check_contrast.py --trace classic "#2F6B3A"   # how every role resolves in custom-colour mode
python -m pytest                                    # tests (pip install pytest)
```

The run must pass: exit code 1 means an enforced pair fails, the dark blocks differ, the lint finds an error, or fallbacks.css is out of date. The full results are in
[`contrast.md`](contrast.md) (generated, never edit it by hand).

**Required ratios.** Text 4.5:1; large text (24 px and up, or 18.66 px bold) 3:1; UI parts that carry meaning (control borders, the focus ring, bar fills, the outline of a marked cell) 3:1.
Pairs marked decor are reported but never fail.

**Result for the current CSS** (1019 pairs across 6 layouts x 2 themes):

| | Pairs |
|---|---:|
| Pass | 1004 |
| Fail | 0 |
| Accepted exception | 1 |
| Decor, below the 3:1 target | 14 |

**Accepted exception.**
* Curling, light theme, `header-line/header-bg`: the red line under the ink header (house red `#C8102E` on `#0E2233`) is 2.76:1. It is a decorative edge: nothing is written in it and the page reads the same
  without it. It is kept as the approved mockup draws it. The dark theme's lifted red passes.

**Decor pairs below 3:1** (reported, not enforced; each has a reason in `contrast.md`):
* `line-strong/surface`, the outline of cards and tables and the dotted divider, 1.5 to 2.0:1 in every layout except Scoreboard (10 of the 14). What is inside the outline is readable without it.
* Classic `header-line/header-bg` (1.22:1 light, 1.31:1 dark), a decorative edge under the header bar.
* `button-bg/bg` in Hockey dark (2.63:1) and Slo-pitch dark (2.77:1). The button's label (`on-accent` on `button-bg`) identifies the button and passes.
* Team chips (`team-N` on `surface` and `bg`) are decor pairs too, because the team's name or code is always beside the chip. All six chips of every layout meet 3:1 in both themes, so none is in the list above.

**Where `won-line` is measured.** Only where it is drawn: on the coloured final panel (Basketball, Classic), on `surface` (Curling, Hockey, Slo-pitch) and on Scoreboard's black digit tiles. Basketball and Classic
cards off the panel underline in `accent`, which is measured as `accent/surface`.

**Marks.** `mark-line` is measured as a UI pair against the card and against the tint it encloses (Scoreboard against its digit tile), because the frame, with the tint and the hidden words, is how a stolen end or run-limit inning is shown.

## Decisions made in stage 3 (confirmed by the owner, 15 October 2026)

1. **League colour model.** A league sets one colour (`colour`) and optionally a dark version (`colour_dark`). Each layout has its own second accent, which a league cannot set. A separate second league colour was
   dropped. This was agreed during stage 3.
2. **Custom-colour mode.** When a league sets its own colour, the page carries `data-league-colour` and each layout re-derives its accents, so any colour that takes white text at 4.5:1 or better passes every contrast
   pair. Without a colour the layout is the approved mockup. A colour that is too light is stopped by the stage 4 build, with a message naming `colour` or `colour_dark`.
3. **Team palettes belong to the layout.** Each layout has its own six team colours, so a team with no colour of its own changes colour when the league changes layout. A team's own hex persists across layouts and is
   lifted in dark mode by the layout's amount. The palette order follows `docs/dark-palettes.md`; Classic uses Curling's six, Scoreboard uses Basketball's five plus grey, and Basketball has a sixth (magenta).
4. **The team card is new.** No mockup shows it. The six variants are built from the Masters site's team card and restyled per layout. Please review them.
5. **Scenes are baked.** The header and footer pictures (Basketball hills and sunrise, curling rings, slo-pitch clay arc, hockey rink lines, dark moon and stars) are SVGs in the CSS. They do not follow the league colour.
6. **Structure the mockups did not draw.** The hero card for curling and hockey; the Scoreboard game row with the time first; the Scoreboard "Next up" black bar for slo-pitch; edges on Classic-Curling's leader tiles;
   no amber outline on Scoreboard's dark lead row in the race.
7. **A corrected number in the curling sample.** "Scored with hammer" for Hurry Hard is 3 of 5, not the mockup's 2 of 5. The ends table shows Hurry Hard with the hammer in five ends (1, 2, 4, 5, 7) and scoring in
   three of them (2, 5 and 7).
8. **Where `won-line` is measured.** Only where it is drawn (see [Contrast](#contrast)); off its panel, Basketball and Classic underline in `accent`.
9. **Marks are never colour alone.** A stolen end or run-limit inning is drawn with a tint, a visible outline (circle in slo-pitch, amber outline in Scoreboard) and hidden words, for WCAG 1.4.1. The penalties table and
   the event log show the team code beside the chip.
10. **Sample minimums.** The sample's leaderboard notes ("Minimum 15 at-bats", "Goalies need 4 games") should become league settings, or `[placeholder]`s, in stages 4 and 5.
11. **Theme toggle.** Its label changes with the page ("Switch to dark theme" / "Switch to light theme") and it has no `aria-pressed`. Stage 4 must hide it until JavaScript runs and store the choice as `st-theme`.
12. **Changed mockup colours and the accepted exception.** See [Mockup colours changed for AA](#mockup-colours-changed-for-aa) and [Contrast](#contrast).
13. **Scope.** `scripts/check_contrast.py` also holds the stage 4 league-colour gate and a browser comparison; `scripts/design_system/sample.py` is hand-written sample data that the stage 5 sample generators will replace.

Questions that still need an answer from the league are in [`open-questions.md`](open-questions.md).

# Stage 4 includes

`_includes/shell/` and `_includes/parts/` print the markup of the part anatomy above from the computed JSON
(docs/stage-4-spec.md 4.1). The specimens in `scripts/design_system/specimens_*.py` stay the reference;
`tests/test_parity.py` renders both for every part, layout and sport and fails on the first differing node
(rules in its docstring and in `tests/parity/htmlcompare.py`). `scripts/design_system/contract.py` converts the
sample leagues into the JSON the includes read, so the shapes below are proved against all four sports.

## Conventions

* An include reads `league` (league.json), `stats` (the season's files: `stats.teams`, `stats.standings`,
  `stats.schedule`, `stats.games`, `stats.players`, `stats.leaders`), `active` and its parameters, never
  `site.data`. `_includes/core/context.html` (page shell) assigns the first three. Parameters are read as `include.x`.
* Sport differences arrive as data: labels, `league.words`, `league.display` hints, flags on cells and columns.
  An include may branch on `league.layout` (as the specimens do), never on the sport (a test greps for it).
* Liquid prints only. Every number arrives formatted, every list sorted; text goes through `escape`; every path
  through `relative_url` (a `mailto:`/`https:` footer link and in-page `#anchors` are printed as written).
* Includes share one variable scope, so every `assign` carries the include's own prefix (`_ls_` for the line score...).
  Output is minified with the capture/strip tail at the bottom of the larger includes, so indentation never
  becomes text; a space that matters (`</span> <span>`) sits on one line.
* Liquid 4 (Jekyll 4.4) has no usable `blank`: test a string or list with `x.size > 0`. Include parameters take
  variables only (no filters, no `a[b]`): assign first. A parameter called `size` reads as the hash size when it is
  not passed, so compare it with the values it may have.
