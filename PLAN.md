# scorers-table: plan

Built in stages. Each stage ends with something to review (a design canvas or
a pull request), and the next stage starts only once it's approved. Each
stage says which Claude model fits it:

- **Opus**: judgement. Architecture, design direction, sport rules, reviews.
- **Sonnet**: building from a clear spec. Most code, tests, docs.
- **Haiku**: cheap, repeatable checks. Screenshot sweeps, link checks, lists.

A stage can run unattended (overnight) once its spec is approved: it ends in a
pull request, never a merge.

Status: stages 0-4 done (October 2026; stage 4, the core, is merged). Stage 5 is under way: **basketball is done and
merged** (spec: `docs/stage-5-basketball-spec.md`) and **curling is done and in review as a pull request** (spec:
`docs/stage-5-curling-spec.md`); hockey and slo-pitch come next, one pull request each.

## Stage 0: brief and plan (done in the Masters website session)
- `BRIEF.md` (what it is, the core, the sports and their club rules, layouts,
  what carries over), this plan, a first `CLAUDE.md`.
- **Model:** Opus. **Review:** you read the brief, especially the club rules.

## Stage 1: phone mockups (done)
A design canvas with the six layouts on a phone (390 px), light and a dark
Home per layout (see `docs/design.md`):
- each sport layout: Home and Game (the line score is where sports differ most);
- Classic and Scoreboard: Home, each shown with two different sports, to prove
  they are general;
- one shared Stats screen per layout where it differs.

Builds on the Masters canvas (Recommended, Classic Club, Scoreboard).
- **Model:** Opus. **Review:** you pick, comment, iterate on the canvas.

## Stage 2: create the repo, first commit
`kylermurphy/scorers-table`, public. Mark it as a template repository

## Stage 3: design system
Turn the approved mockups into tokens and components: colour variables per
layout (light and dark), type scale, spacing, the shared parts (result card,
line score, standings table, leader row, game row, team card, next game panel).
A `docs/design.md` and the CSS variables.
- **Model:** Sonnet, with an Opus look at the result.

**Delivered** (merged):
- `assets/css/`: `fonts.css` (self-hosted fonts in `assets/fonts/`), `tokens.css`, `layouts/<id>.css` for
  the six layouts (every colour role in light and dark, plus a custom-colour mode for a league's own
  colour), `base.css`, `parts-shell.css`, `parts-scores.css`, `parts-data.css`, `fallbacks.css`.
- `docs/design.md` (the reference and the decisions for the owner), `docs/contrast.md` (generated),
  `docs/open-questions.md`, `docs/dark-palettes.md` (with a note on where the CSS differs).
- `docs/design-system/index.html`, generated by `scripts/build_design_system.py` from
  `scripts/design_system/`: every token and part in six layouts, light and dark.
- `scripts/check_contrast.py` (WCAG AA for every pair, the league-colour check stage 4 calls),
  `scripts/build_css_fallbacks.py`, and `tests/test_check_contrast.py`.

**Deferred to stage 4:**
- Jekyll includes ported from the specimen markup, and the showcase rendered from them.
- The `league.yml` colour schema (`colour`, `colour_dark`), the `data-league-colour` attribute and
  the `check_league_colour` gate in the data check.
- `site.js` for the theme toggle (hidden without JavaScript; stores `st-theme`) and the logo image sizing.
- Contrast and test checks in CI.

## Stage 4: the core
The sport-neutral skeleton, with no sport yet beyond a stub:
- data model: `data/seasons.yml`, per season `teams.yml`, `players.yml`,
  `schedule.csv`, `games/`, `drafts/`;
- `league.yml`: name, sport, layout, colours, logo, standings rule,
  tiebreakers, search engines, contact;
- the build script: load, check (problems with paths), standings engine with a
  pluggable points rule, calendars, stub pages, the active season and sample
  switch;
- Jekyll layouts and the shared parts; CI (tests, build, link check, deploy to
  Pages).
- **Model:** Opus designs the sport-folder interface (a short spec reviewed
  first); Sonnet builds it.

**Delivered (spec: `docs/stage-4-spec.md`):** `league.yml`; the data loader and checks with box paths
(`scripts/core/loader.py`); the sport interface (`sports/<id>/`: `sport.yml` + `check`, `read`, `present`,
`derive`) and the `stub` test sport with made-up sample seasons; the standings engine with a pluggable points
rule and named tiebreakers (Opus-reviewed against the Masters site); compute, calendars and an atomic writer;
`scripts/build.py`; one Jekyll include per design-system part, kept equal to the stage 3 page by a parity
test; the pages, head, theme toggle and sample banner; CI (tests, contrast, build, Jekyll, preview, link check,
deploy). **Left for stage 5:** the real sports and their extra parts (event log, roster, numbers, facts, top
performer, penalties), JS rules ports, and the `line_score` extras a sport needs. **Left for stage 6:** the
screenshot sweep across six layouts per sport and small CSS for empty states.

## Stage 5: one sport at a time, one PR each
Basketball first (ported from the Masters site, so it can be checked against a
real league), then curling, hockey, slo-pitch. Each PR adds the sport folder:
game file format and docs, rules in Python with shared test fixtures (the
JavaScript copy moves to stage 7, see below), stats, the line score and game
page, a sample season generator, and the sport's default standings rule.
- **Model:** Sonnet builds; Opus reviews each PR for rule mistakes.

**Basketball: delivered (merged).**
- `sports/basketball/`: `sport.yml`, `rules.py` (`check`, `read`, `present`, `derive`), `sample.py`, the README (the
  game file box by box), and 89 shared fixture cases (`fixtures/`) for the stage 7 JavaScript port. The Masters rule
  (1 point per quarter won, 3 per win) is a documented preset, not an option.
- `convert_masters.py`: a Masters data folder in, a scorers-table `data/` folder out; `tests/test_masters_parity.py`
  compares the two sites' numbers when `MASTERS_SITE` points at a Masters checkout (local only, never in CI).
- Four small core extensions that any sport can use: the `top_performer` block, rates ranked before rounding,
  leaderboard keys (`zero`, `playoffs`, `home`, `player_rank`) and `stats.columns` (the column lists).
- `league.yml` now ships `sport: basketball`; the committed `data/sample-*` are basketball seasons; golden files
  are per sport (`tests/golden/basketball/`), and the stub stays the core's test sport (`demo: false`).
- **Sport previews** (owner request): `sport_previews` in `league.yml` builds a made-up demo league per sport at
  `/<sport>/` on every deploy (`scripts/preview_root.py`, `scripts/build_preview.sh`), beside `/preview/`. That is
  stage 8's "live demo for each sport", made early; it grows by itself as each sport lands.
- Docs: `docs/sports.md`, `docs/data.md` (examples are basketball), `docs/open-questions.md` section 5 (the new
  placeholders and the questions for the owner: the foul limit, the forfeit score, confirming decisions 3, 4, 6, 8, 9).

**Curling: delivered (in review as a pull request).** All 13 decisions in the spec were confirmed by the owner as
recommended (October 2026).
- `sports/curling/`: `sport.yml`, `rules.py` (`check`, `read`, `present`, `derive`: the hammer walk, steals, blanks,
  big ends, extra ends, concessions and time called, lineups with spares), `sample.py` (Pine Lake Curling Club), the
  README (the score card box by box, the how-tos and the rink-name warning) and 97 shared fixture cases for the
  stage 7 JavaScript port.
- Core extensions any sport can use: the `numbers` ("The game in numbers") and `roster` (lineups) blocks, each with
  its include, parity case and specimen; the card's own `line_score` and `meta_extra`; `words.extra` (the extra-end
  word: "Final · EE", "an extra-end win"); `display.results_legend`; `display.team_sub` (the skip line on a team
  card); a player group with no counting stats (`stats.player: []`: games played only); and the sample generator's
  `TIMES`, `SURFACES`, `NUMBERS`, `POSITIONS` and `NOTES`.
- Two small core fixes found by the sample: a past season's game page highlights Archive (not Schedule) in the
  navigation, and a forfeit is not a game in a team board's "in N games".
- Golden files `tests/golden/curling/`; the `/curling/` sport preview comes by itself (`sport_previews: true`). The
  shipped `league.yml` and the committed `data/sample-*` stay basketball.
- Docs: `docs/sports.md` (the new keys and blocks), `docs/data.md` (curling examples, the rink-name rule),
  `docs/open-questions.md` section 6 (curling's five placeholders and the 13 decisions), `README.md`.
- Not built, named in the spec: the club-scoreboard line score, team rates ("ends won %"), a printable curling score
  card and photo-reading prompt (both "Later"), and the JavaScript rules and entry page (stage 7).

**Decided: the JavaScript copy of the rules moves to stage 7**, with the entry page, its only user. Each sport's
pull request still commits its shared fixtures, so the port can be tested against them.

**Still to come, with the sport that needs it** (deliberately not built yet, so no option goes untested; `order: asc`,
`format:`, option-chosen period words and option-shown stats are the basketball spec's "Deferred" table):
- Hockey and slo-pitch folders, each with its sample, golden files, README and fixtures (the same package shape as
  basketball and curling).
- The extra display parts still missing from stage 4's list: `facts` (slo-pitch), `events` (hockey's scoring
  summary) and a penalties table (hockey), each a reusable core part with a specimen and a parity case (the design

- Leaderboard `order: asc` (lowest is best): hockey's goals-against average, where 0.00 is valid.
- A `format:` for rates (`.333`, `.912`): slo-pitch's average, hockey's save percentage.
- Period words chosen by an option: basketball halves (the Masters sheet had halves until October 2026).
- Stats and boards that show only when an option is on: basketball with free throws not kept (and curling with
